# Aggregation Hub 前端页面设计

> 文档编号：UI-001  
> 状态：设计评审中  
> 平台：Windows 优先桌面应用

## 1. 目标

用户应在五分钟内添加第一个 Provider 并完成客户端接入；始终知道网关状态、地址和异常；清楚 Provider、模型、请求与费用关系；高风险操作说明后果；默认隐藏秘密与请求正文；支持键盘、缩放、亮暗主题和中文。

## 2. 信息架构

```text
Aggregation Hub
├── 概览
├── Provider
│   ├── 列表
│   ├── 新建/编辑向导
│   └── 详情
├── 模型
├── 客户端接入
├── 请求记录
├── 用量统计
├── OAuth 账户
├── 诊断
└── 设置
```

顶部固定显示网关状态、Data Plane 地址、启动/停止和全局异常。地址可复制，完整 Local Key 不常驻显示。左侧导航有文字、图标和异常徽标。

状态同时使用颜色、图标和文字：正常绿、处理中蓝、警告黄、失败红、禁用灰。

## 4. 首次启动向导

1. 欢迎：说明本地运行、回环监听、不自动改配置、不保存正文。
2. Local Key：只显示一次，提供复制和“已保存”确认；关闭后只能轮换。
3. 添加 Provider：允许稍后添加。
4. 同步模型并执行最小真实测试。
5. Claude Code/Codex 接入配置。

## 5. 概览

卡片：网关状态、Provider 数、模型数、今日请求、Token、估算费用。价格未知显示 `—`，不能显示 `$0.00`。

趋势：最近 7 天请求、成功率、Token、费用和 Provider 分布。异常区优先展示 OAuth 需授权、认证失败、端口冲突、数据库/CredentialStore 异常和能力测试失败，并提供操作按钮。

### 5.1 当前已实现的 Phase 1 桌面基线

当前主界面实现为最小可用概览：展示 Core 运行状态、Data Plane 地址与版本；提供刷新、启动或重启操作；展示已接入 Provider 的安全摘要；以及创建一次性 Local Key 的表单和复制按钮。

WebView 只能调用 `dashboard_status` 与 `create_local_key` 等 Tauri Command，不能读取或构造 Control Plane URL、管理令牌、CredentialStore 引用和完整上游凭据。完整 Local Key 只存在于创建成功后的当前组件内存；用户关闭或刷新页面后不恢复。网关未运行时必须禁用创建 Local Key 操作，并提供可理解的等待提示。

该基线不是完整 Provider 管理、模型、用量、OAuth 或诊断页面；这些页面继续按本设计文档的后续章节实施。

## 6. Provider

列表列：名称/slug、类型、Base URL 主机、凭据状态、模型数、健康、延迟、启用、操作。支持搜索、类型/状态筛选和分页。

创建/编辑向导：

- 基本信息：类型、名称、slug、Base URL；
- 认证：API Key/Token 或 OAuth，已配置只显示掩码和“替换凭据”；
- 网络：超时、自定义 Header、本地地址确认，TLS 固定开启；
- 测试：URL、DNS、TLS、认证、模型接口分别显示；
- 模型：同步后勾选启用，不默认启用全部；
- 确认：展示最终 Public Model ID，不重复显示凭据。

Provider 详情含概览、模型、健康、用量和设置。危险区包含禁用、删除、替换凭据。

## 7. 模型

列：Public Model ID、Provider、上游模型、能力徽标、上下文、价格来源、状态和启用。

能力徽标：Stream、Tools、Parallel Tools、Reasoning、Thinking、Vision。详情显示能力来源、用户覆盖、最近测试、使用和价格历史。覆盖能力需确认，并可恢复到上游声明。

## 8. 客户端接入

顶部显示 Data Plane URL、现有 Key 的前后缀、创建新 Key、健康和鉴权测试。

Claude Code 页：Base URL、Local Key 环境变量占位符、模型 ID、Messages/Tool 测试。Codex 页：自定义 Provider、Responses wire API、认证环境变量、模型和 Tool 测试。

现有 Local Key 只保存哈希，应用不能再次显示完整值。用户复制带占位符的模板，或创建新 Key 并在当前页面一次性复制完整配置。模板由受测试生成器生成，不能散落硬编码字符串。

## 9. 请求记录

列表：时间、请求 ID、协议、Provider、模型、状态、首 Token、总耗时、Token 和费用；支持时间、Provider、模型、协议、状态、错误筛选。

详情只显示路由、时延、Token、错误摘要和取消状态，明确提示默认不保存 Prompt、回复和 Tool 参数。

## 10. 用量、OAuth、诊断、设置

用量支持日/周/月、Provider、模型、Token 分类、请求量、成功率和费用；未知费用与已定价数据分开。图表必须有表格替代。

OAuth 卡片显示 Provider、账户标签、状态、过期、最近刷新、重新授权和撤销。授权打开系统浏览器，应用显示等待与超时；不在 WebView 中接收 Token。

诊断页显示版本、数据库、CredentialStore、端口、健康和脱敏错误，并允许生成诊断包和打开数据目录。打开目录由 Rust 执行固定路径，不接受前端任意路径。

设置包括端口、超时、优雅退出、保留期、备份、开机启动、主题、语言、更新、安全密钥和实验 OAuth 开关。

## 11. 危险操作

删除 Provider、替换凭据、撤销 OAuth/Key、改端口并重启、清理历史、恢复备份、退出并中断请求必须二次确认。文案包含对象名和后果，按钮使用具体动作名称。

## 12. 异步与可访问性

- 保存期间禁用重复提交；
- Provider 测试可取消；
- 页面离开取消无价值查询并忽略过期响应；
- PATCH 用版本号处理冲突；
- 所有页面有加载、空、错误、成功状态；
- 语义 HTML、可见 Label、错误关联、弹窗焦点锁定和恢复；
- 状态不只依赖颜色；
- 支持 200% 缩放和 reduced motion；
- 配置片段使用等宽文本区和独立复制按钮。

## 13. 前端代码边界

```text
src/
  app/ pages/ features/ components/
  services/ schemas/ hooks/ stores/ styles/
```

Server State 与 UI State 分离；页面不写 Provider 业务规则；响应做运行时 Schema 校验；不使用 `dangerouslySetInnerHTML` 渲染上游内容；完整凭据不进入 Store、URL、localStorage 或 sessionStorage；大型图表按页懒加载。
